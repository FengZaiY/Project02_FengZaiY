# 运行性能优化验证（2026-11-02）

环境：Windows，Node v24.16.0，源码版本 0.1.19。保留前一轮 README 与状态摘要校正；本轮交付源码与原开发预览，未更新安装包、提交或推送。

## 实现

- 目录接口在 SQLite 内提取标题、父级、精确顺序及分支/发送状态，避免把整篇正文和附件数组传入 JavaScript；完整内部笔记树与轻量目录共用原层级构建函数。没有新增正文缓存。
- 中文标题排序复用比较器，保留中文排序、同名稳定顺序及精确分数排序。
- 旧逻辑清空统计复用当前头元数据，只对全部分支均已清空的实体统计完整历史；文件任务、目录存在性及清理状态继续实时读取。
- 不改持久化结构、记录校验、同步格式、UI 协议、权限或保存冲突规则。

第一次适配复跑在同级排序后的保存等待中超时，截图显示版本冲突且输入保留；增加请求记录的隔离诊断复跑通过。原脚本在输入后执行拖动和截图，自动保存可能在落点前发出，导致场景变为旧版本写入交叉。现先定位和截图，再插入同级笔记文字并断言处于 queued，随后释放拖动，明确验证待保存输入在排序后保留；生产保存逻辑未改动。最终原脚本完整通过，日志为 `test-note-drag-final.log`，此前两次失败分别保存在 `test-note-drag.log`、`test-note-drag-retry.log`；不声称消除了所有并发保存冲突。
