实际失败对话的两次提交尝试仅调用读取接口，均未调用 propose，随后出现重复空浏览器工具调用；没有 FengZaiY 拒绝该方案的接口错误证据。遗漏内容已在上一轮通过正式 MCP 补交并回读为三项待确认方案。本轮不重复创建方案或替用户确认。

## 变更

- 内置 Skill 增加方案提交步骤：内容准备完成后调用 propose，使用方案 ID 回读，区分未提交、接口明确失败、已提交未核实、待确认和确认入库。
- 明确纯提交阶段不能以浏览器控制、截图、空脚本或 bootstrap 代替写入；第一次无关结果即停止该路径。实际来源阅读不受限制。
- 响应不明时优先回读，只有原 requestId 与完整参数都保留才原样重试；否则查询候选并核对，避免换 ID 重复提交或只替换过期版本。
- API 及 MCP 初始化、bootstrap、record、propose 描述同步指向实际业务工具和核验结果。没有新增权限、工具、协议字段或自动确认路径。
- 隔离 SDK 测试补充：只读取不创建方案；服务端已写入而调用方未使用响应后，新连接以原参数重试只返回同一份方案；完整回读并保留原笔记；不同请求正文和过期目标拒绝。
