# 附件去重与预览合并验证

日期：2026-10-14。环境：Windows、Node.js 24.16.0、Playwright/开发 Electron；功能测试使用 `artifacts/` 隔离资料。未生成安装包。

## 实现范围

- 界面同库导入按 SHA-256 与大小复用非回收、非冲突的已有资料，保留名称、标签、敏感性、保留状态及健康的已整理原件路径。缺失原件经校验后重新绑定；并发导入串行。
- 明确“导入为独立资料”仍可另建附件身份。不同知识库不自动复用；Agent 上传保持原有独立请求与幂等规则。
- 资料列表/详情的“合并相同内容”先预览、选保留项和列出受影响内容，再确认执行。标签并集、敏感及保留状态不降低。
- 当前正文链接、媒体、附件列表、来源及提案等引用创建新版本；冗余条目回收。事务失败整体回滚，原件和历史保留；过期、未保存、冲突、跨库或不支持的引用阻止执行。

## 原工作区

核实原 13895 端口、启动目录、占用锁与实际目录后，以同一入口重启并刷新。前后 160 条修改记录及当前分支摘要完全一致，1 个原知识库、1 篇正式笔记和 7 项附件保留，7 个原文件 SHA-256 一致。后台目录无缺件或错误。只读合并预览识别 2 份相同图片、1 篇受影响笔记且无阻塞。

未对用户实际附件确认合并、回收、物理删除或迁移。测试并未改写正式资料。相关比对结果在 `artifacts/dedup-preview-before.json` 与 `artifacts/dedup-preview-after.json`。

## 边界

本轮不做不同附件 ID 的物理存储归并，不释放磁盘。历史引用保持原 ID，需要时恢复旧附件后预览；不建立新别名协议。自动合并最多 100 项，不支持的 Markdown 引用形式需先在笔记中保存。远端同步并发编辑仍保留冲突，不声称可预知离线电脑的新引用。

未运行真实百度双机联调、GB 大文件/超大资料库性能测试、真实付费模型或安装包测试。既有安装包不包含此后的源码更新。
