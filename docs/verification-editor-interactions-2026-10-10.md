# 拖放布局与自动保存验证

日期：2026-10-10。环境：Windows、Node.js v24.16.0、Chromium / 开发 Electron；资料均来自 `artifacts/` 内隔离工作区。本轮仅源码与界面构建，未生成安装包。

## 实现与证据

- 文件拖入：两张图片、视频和普通文件导入为稳定附件引用，保留对应知识库。失败与成功文件混合拖入时，成功项仍保留。桌面以真实 File 经 preload 取得路径，复用受限导入入口；合成 File 不得伪造路径。
- 布局：拖动柄重排、左右并排、恢复纵排、鼠标角部缩放、对齐、自适应；附件链接/表格/高亮块使用普通可编辑容器。横排不足时换行，块操作按钮与标题不重叠。普通容器的固定高度在历史阅读中也生效。
- 内容保留：刷新重开保持尺寸、顺序与附件引用。核心测试验证新布局的尺寸上限、嵌套附件范围检查、v3 完整同步、原件哈希及重复接收。
- 自动保存：约 1.5 秒防抖，手动保存与自动保存串行。切换笔记不写错对象，请求处理中继续输入使用正确的新基础版本；无修改的手动保存不重复生成历史。保存成功不重建编辑器。
- 失败与冲突：保留草稿、显示状态、暂停自动重试。手动可重试，基础版本冲突只有显式确认才创建并发分支；确认分支后的本地保存状态与待处理冲突分别呈现。

## 原预览与限制

只读核对 13895 的监听进程、实际根目录、知识库、笔记和三项附件，均指向原工作区；没有改用 13906 的隔离空库。页面和持久化工作区均显示原笔记存在未保存编辑，存储没有待应用变更，Agent 未开启，同步未忙。为保留用户编辑，本轮未重启该服务、未刷新原标签、未点击保存。

新界面构建已可由原地址提供，用户先保存现有编辑再刷新即可加载。服务端新布局边界校验已在隔离服务验证；原预览进程仍使用此前模块，待正常保存后按原启动参数重启生效。没有把这一点记成已完成服务更新。

浏览器拖入单文件上限为 128 MiB，较大文件使用桌面版；不扫描目录。位置调整是文档内顺序、并排和对齐，不是任意坐标悬浮。图表内部仍采用源文本，画板对象沿用原有编辑器；第三方 Markdown 阅读器不保证还原布局。两台电脑须更新后编辑新节点。

未运行安装包构建/测试、GB 文件性能、真实双机部署或付费模型。没有修改用户正式资料、自动操作网盘客户端或安装其他 Agent 的 Skill 副本。
