# 根目录与知识库文件夹验证

日期：2026-10-09。环境：Windows、Node.js 24.16.0、开发版 Electron、Playwright。写入测试仅使用 `artifacts` 下隔离目录，不使用用户资料作测试。

## 本轮实现

- 系统设置明确“系统工作目录（根目录）”，提供选择/修改入口；空目标经确认使用迁移，已有工作区经确认使用切换，保留原两个独立入口及重启生效机制。
- 新建知识库在根目录直接创建真实文件夹，以本地相对路径映射和所有权标识关联稳定 ID；新建失败回滚知识版本及映射，不覆盖现有目录。
- 知识库管理展示实际文件夹路径，支持复制，桌面支持打开；新建表单显示根目录。改名、删除、恢复不物理重命名或删除文件夹。
- 新 UI/Agent 附件导入存入对应知识库的 attachments；旧附件绑定保持兼容。笔记与历史仍由根目录 SQLite 统一保存，不拆库，不自动导入手工放入文件夹的文件。
- 旧库、同步与恢复后的库按实际记录派生本机目录，不改旧事件及哈希，不将目录路径暴露给外部 Agent。

## 未验证与边界

- 未运行安装包构建/打包验证，不更新旧安装包；未做真实网盘双机、付费服务测试。
- 文件夹不是独立工作区，也不承诺脱离数据库直接编辑笔记。同期写入整个根目录到网盘仍不受支持。
- 新目录创建后若磁盘写入失败，可能保留未完成目录，但不会将其显示为已提交知识库；不递归清理用户可能已放入的文件。
- 知识库改名保留创建时目录名，可在管理页查看实际路径。不要手工改动应用的文件夹名或所有权标识。
- 本地目录映射不随同步或独立备份分享。旧附件、同步/备份对象可继续使用原共享路径，不在本轮强制移动。
- 超大资料库性能、硬件断电、系统权限异常的所有组合未实测；不以模拟通过宣称覆盖所有机器。
