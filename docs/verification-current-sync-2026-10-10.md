# 当前内容同步验证

日期：2026-10-10。环境：Windows、本机 Node 内置 SQLite、Playwright Chromium 与开发 Electron。所有自动化写入使用 `artifacts/` 下隔离资料，不使用真实百度账号，不生成安装包。

## 实现

- 当前 Service 改用 v3：每设备最新加密清单、自包含修改记录、不可变二进制对象；运行时不依赖 Git，不提供独立备份入口、RPC 或后台任务。
- 笔记自动保留修改记录，仍可逐条恢复；恢复产生新修改，保留之后的历史及并发分支。
- 发布冻结已保存内容，估算空间，按批次及实时剩余空间生成；支持暂停、重启继续、取消和批次上传确认。最新清单最后写入。
- 大文件组装逐块校验、flush 和持久化断点；再次接收先核对本地前缀，损坏位置后重新取得，完整校验后才关联。
- 新电脑直接合并各设备最新清单，不需旧 Git 包或历史发布顺序。缺对象拒绝完整导入，非主力机可明确只收笔记与索引。
- v2 中断日志恢复其知识记录及路径绑定，不执行 Git；旧仓库、旧包与旧备份保留。设备释放保护与外部 Agent 权限边界继续保留。

## 边界

- 本轮未运行真实百度双机传输、GB 级视频压力测试、十万级修改历史性能测试或安装包验证。接受百度同步空间能力，不等于已经替用户核验云端上传。
- 所有电脑需升级到 v3；已有电脑先发布一次最新内容，新电脑使用同一同步目录和配对密钥接收。旧 v2 云端包不能直接当作 v3 最新清单。
- 按批生成控制新增中转占用；上传及“仅释放本地”仍由百度客户端完成，不自动删除同步对象腾空间。
- 清单上限 32 MiB；历史按约 2 MiB 分片，但完整校验仍在内存汇集历史。超大规模性能及长期不可变对象清理尚需后续优化。
- 恢复百度历史清单需要对应对象及密钥。已有工作区导入旧清单只合并历史，不静默回滚更新的笔记；逐条笔记恢复在系统内操作。
- 主力机仅供历史的原件释放仍保守禁止，非主力机按当前主力回执、使用状态及未发布修改限制释放。
