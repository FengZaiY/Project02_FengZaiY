# StudySelf 同步验收与可选双机联调

更新日期：2026-10-10。百度同步空间是用户已确认采用的传输依赖，不再要求客户端能力验证或问卷。此清单关注 StudySelf 的实现责任，真实部署联调按需进行，不作为开发或原件释放的前置条件。

## 系统验收范围

在两个或多个隔离工作区中模拟 v3 目录交接，使用独立 SQLite 和同一配对密钥；当前应用不依赖 Git。同步目录不得包含工作区或旧 Git 仓库；密钥不明文上传。只用测试资料，执行结果按实际轮次记录在 [验证记录](verification.md)，本清单本身不表示通过。

| 项目 | 系统应保证 |
|---|---|
| 错开交接 | A 发布后关闭，B 稍后收到文件仍可导入；反向同样成立，不要求双方同时在线 |
| 编辑保护 | 未保存标签拒绝拉取；已保存修改按父记录合并，不需要提交 |
| 发布快照 | 冻结已保存内容；发布期间的新修改留待下次发布 |
| 并发 | 不同记录合并；同一记录保留双方并提示冲突，不按时间覆盖 |
| 乱序、缺块、重复 | 不依赖旧快照；清单/分块未齐时拒绝完整导入，到齐重试不重复写入 |
| 空间批次 | 预估、实时余量检查、保留空间、批次上限、暂停继续和重启保留进度 |
| 组装断点 | 前缀 fsync 后记录进度；重启复核有效前缀，损坏回退到首个坏块，不重新下载有效前缀 |
| 中断、损坏、错误密钥 | 失败不报告完整；发布/导入日志恢复，不静默换密钥或丢修改 |
| 原件完整性 | 图片、文档、素材、回收站文件及视频均纳入；校验分块和全文件哈希，缺失/未下载不表示删除 |
| 索引导入 | 仅非主力机明确选择；原件保持待下载，下载交接块后可校验恢复 |
| 非主力机释放 | 无当前主力角色文件回执、未保存/未发布、冲突、使用中、保留或本机文件链接引用时拒绝；仅删除系统托管原件，不删除同步文件 |
| 主力角色 | 主力原件保留；角色冲突暂停释放；接管须确认，当前资料不齐不能成为主力机 |
| 新设备 | 只凭各设备最新清单及引用对象一次重建资料和笔记历史，不依赖源电脑在线或旧发布 |
| 历史与回收站 | 修改与删除自动留下记录，恢复形成新记录；不需要 Git |
| 工作区 | 接续不强制替换本机标签，不携带未保存草稿或退役聊天状态 |
| 退役入口 | 没有 Git 提交/整库版本和独立备份入口、服务方法、定时执行；旧文件不删除 |
| 云端旧清单 | 仍须匹配对象及密钥；已有库合并保留较新历史，不误称整库回滚 |
| 状态准确性 | 区分本地生成、用户确认上传、本机校验和主力回执；不将目录中文件存在当作已上传 |

测试还需覆盖取消客户端问卷后的行为：无问卷记录可以正常按系统规则释放；旧问卷记录不删除、不自动改为通过、不赋予跳过回执的权限。

## 可选双机部署联调

需要排查实际使用环境时再进行，不要求用户重复验证百度自身的成熟功能。

1. 两台 Windows 使用相同源码版本，设置不同设备名，各自配置同步目录和同一密钥。旧资料须由更新后的电脑发布 v3，旧协议不混写。
2. A 校验当前资料、设为主力机，直接发布全工作区内容；B 无需创建共享提交。
3. A 编辑并保存、预估空间、分批发布，在百度客户端确认上传后关闭；B 下载后直接拉取最新内容，再反向重复。核对 StudySelf 的内容、原件、修改历史和回执。
4. 如遇问题，记录应用版本、设备、日期、失败操作及证据；只有与问题有关时才补充客户端版本和设置，不记录账号凭证。

本轮未执行真实设备联调；这不是待用户完成的开发阻塞项，也不等同于已有实测通过记录。

## 系统后续重点

- 分批发布和断点续传已实现；后续优化长期对象空间管理和大资料量的资源消耗。
- 主力机历史孤立原件的引用核算和手动释放；当前主力机全部原件保留。
- 独立备份功能已取消；云端恢复依赖最新/历史清单、引用对象和独立保存的密钥。
- GB 视频、长历史及故障恢复的性能和资源消耗。

百度负责网络传输；StudySelf 不直接操作客户端或查询云端。中转密文使用官方客户端“仅释放本地”处理，不用普通删除模拟释放，不自动清理云端历史。
