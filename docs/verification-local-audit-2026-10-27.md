## 已发现并修复

| 问题 | 原因与修复 | 本轮证据 |
|---|---|---|
| 订阅付款撤回后不能重新付款记账 | 确定性账期身份仍有回收版本，却按新实体提交空 parents；确认付款时复用已回收且无冲突的身份及当前基础版本，不重复创建有效付款 | `tests/local-audit.test.mjs`、业务界面付款→撤回→更正金额重新记账 |
| CSV 导入撤回后不能重新导入 | 同样忽略了原导入身份的回收版本；预览展示当前 parents 并纳入确认摘要，提交重验，永久清理及冲突继续拒绝 | 同上；旧预览拒绝、新预览成功，金额只计算一次 |
| 首次密码保存撤回后打不开编辑器 | 读取默认选择删除版本并报错；现在返回空秘密表单和当前基础版本，旧密文历史仍需解锁才能查看 | 核心测试验证空表单、历史取回、再次保存及数据库无秘密明文 |
| 修改资金账户期初日期可使已有账目退出统计 | 只验证新账目，没有反查账户已有记录；现在阻止期初日期晚于现存收支或转入记录 | 核心失败复现及修复后回归 |
| 业务表单连续保存可能重复创建，切页偶发空引用 | 保存请求未串行，旧表单事件引用全局 activeForm；现在串行提交、保留保存期间的新输入，新建等待保存完成，忽略已脱离页面的表单事件 | `scripts/test-local-audit-ui.mjs` 暂停请求后补充输入、连续保存、旧表单事件及窄窗验证 |
| 密码保存期间继续输入或重复提交存在丢失/冲突风险 | 秘密提交前拍下快照，响应后关闭编辑器；现在提交期间暂时禁用秘密输入和按钮，失败恢复控件，原密文草稿保留 | 业务界面请求暂停验证、源码 Electron 密码与退出回归 |
| 回收的新业务记录缺少恢复入口 | 详情只从正常记录列表获取当前状态，回收项不在该列表；现在使用直接读取的记录状态，回收详情只读并显示恢复入口 | 真实界面创建项目/子任务、回收子任务、从回收站打开并恢复 |
| 中文 CSV 退款/订阅字段不能映射 | 核心支持相应字段，表单缺少列名选择；补齐 refundOf、subscriptionId、period、importKey 映射 | 中文表头退款 CSV 预览→导入→报表→导出 |
| MCP 将引用保护等可处理错误隐藏为 ERROR | 工具层错误白名单落后于业务模块；保留明确的引用、未保存、重复、永久清理、忙碌和退役错误，不透传未知内部异常 | 实际 SDK 调用验证 REFERENCED、ASSET_REFERENCED、权限/撤销/幂等保护 |
| 内置 Skill 脚本读到文本结果时返回 undefined | 错把标准 JSON 文本结果当成 `{value}` 包装；优先读 structuredContent.value，否则直接解析文本结果 | 无 structuredContent 的协议回归；实际脚本创建和读取账号、撤销后拒绝 |

修复不改变已有事件身份、哈希、加密格式或同步格式，不重建数据库。财务、CSV 重做产生新修改记录，保留原历史。修改来源/批次仍沿用原有事务与基础版本校验。

## MCP 与 Skill 能力判断

当前提供 **28 个具名工具**，覆盖知识收集/草稿/来源/方案/正式笔记更新/关联/回收，及八类公开个人实体、财务报告、批量业务写入、订阅付款和资料集合关联。实际 SDK 验证工具发现与实现清单一致；新增业务工具逐个串联执行，脚本客户端与宿主工具共用幂等记录。

在已确认的权限边界内能力完整。以下是有意保留的边界，不是漏接口：密码秘密/主密码/恢复密钥、用户确认入库、批次撤回、永久删除、知识库和系统路径管理、设备/同步管理、任意 Service RPC 均不开放；单附件 MCP 导入/读取上限16 MiB，更大文件使用系统界面。尚未逐一联调第三方 Agent 宿主，不把官方 SDK 或随附脚本测试当作所有宿主已通过。

Skill 前置 bootstrap、最新偏好、业务字段、秘密边界和失败处理已与实现核对；内置协议文档更新，UTF-8 `quick_validate.py` 通过。外部已安装副本未改写，需用户在系统设置中按既有流程更新。

## 排除项与限制

- 不进行多电脑同步验收：目录传输、format7互通、设备角色/停用、远端并发和删除传播等均排除。`scripts/test-local-audit.mjs` 保存选择清单并排除传输及设备测试文件、混合文件中的相关场景；没有使用全量 npm test 冒充本机覆盖。首次粗筛200项中含少量存储合并兼容场景，最终清单进一步按测试体排除。桌面存储迁移沿用测试中的本机同步配置保留检查、退出后的同步入口导航，但未执行双机传输。
- 不执行安装包构建、签名、真实安装/卸载、正式发布或外部已安装 Skill 更新。
- 本轮覆盖功能链与已知风险，不构成“系统不存在任何 bug”的保证；真实硬件休眠/断电、所有第三方文件格式、长期负载和各 Agent 宿主仍有环境差异。
- 先前截图中的原生 `0x80000003` 异常本轮未复现，不能仅凭测试通过断言所有环境中的原生崩溃均已消除。
