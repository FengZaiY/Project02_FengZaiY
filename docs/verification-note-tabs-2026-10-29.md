# 笔记标签切换验证（2026-10-29）

环境：Windows、Node.js 24.16.0、项目现有 Playwright / Chromium 与 Electron。全部交互写入使用 `artifacts/` 下本次独立临时工作区；没有操作正式资料或同步目录，没有打包、提交、推送。

## 行为与实现

- 普通点击 A → B 替换当前标签，笔记树、列表、草稿及内部笔记链接共用入口；已打开目标只激活，不重复新增。
- Ctrl+单击、中键、右键“在新标签打开”、聚焦行后 Ctrl+Enter 显式新增；新建笔记和新建下级笔记继续另开标签。
- 替换前串行保存当前笔记并排空保存期间的新输入，持久化本机草稿后才移除旧标签及保存任务。失败、冲突、输入法组合或进行中的导入不丢编辑、不自动创建并发分支；明确新标签可以保留原冲突草稿继续查阅其他内容。
- 笔记打开、侧栏切页与关闭标签串行执行；缺失目标保留原页，快速点击最后到达用户最后选择。重复点击当前未变化笔记保留原编辑器和撤销。
- 最多 200 条阅读位置保存在本机 workspace，不进入共享标签记录。替换清理失效页面位置，刷新恢复当前页；标签栏在渲染结束及窗口调整时让选中项可见。

## 首轮失败及处理

1. Ctrl+Enter 首轮未触发按钮点击：新增明确键盘处理后通过。
2. 树拖动旧断言仍要求带 ID 的旧正文路径：按当前可读目录映射检查祖孙层级、投影归属和真实正文；首次适配误用绝对键，核对实现后改为相对路径，完整脚本通过。后台标签场景和删除回退场景改用 Ctrl+单击明确建立多个标签，保留原保护断言。
3. 树拖动重复点击当前页时遇到异步重建窗口：相同版本的当前笔记直接保持原编辑器；完整脚本通过。
4. 初次标签滚动发生在图标布局完成前，窄窗仍有裁切：滚动移到完整渲染后，并加入窗口调整处理；专项验证切换、刷新与调整宽度。
