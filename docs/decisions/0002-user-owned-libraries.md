# 0002：用户自建知识库与固定范围标识

日期：2026-10-09。
状态：已采用；用户要求取消预设领域并增加知识库管理。

## 背景

此前界面把需求举例误作为固定领域，并用名称直接隔离笔记和 AI 对话。直接替换名称会影响历史、草稿、同步和对话引用。

## 决定

- 新工作区不创建任何领域、知识库或示例资料。
- 新增 `library` 共享实体：名称和说明可以修改，范围标识固定。
- 新知识库使用实体 UUID 作为现有 `domain` 字段的值；显示时解析为名称。
- 已有资料按实际存在的 `domain` 建立只读兼容目录。第一次人工编辑才创建共享元数据，旧正文和历史不改写。
- 兼容目录 ID 由旧范围确定，两个设备同时编辑会形成可见的版本冲突，而不是两个互不相关的目录。
- 删除仅允许空库，回收站资料也计为非空；不级联删除。远端新增内容遇到已删除目录时仍可发现资料并恢复目录。
- 空白工作区可打开 AI 面板，但必须选定知识库才能发送。未发送问题和对话引用分别保存在各库的本机工作区中。

## 兼容与验证

参与同步的电脑都需使用 0.1.1 或后续兼容版本；0.1.0 不认识新实体，不保证向旧客户端写入兼容。旧知识版本和备份保留读取兼容。

核心测试覆盖目录为空、稳定改名、旧资料投影、并发名称冲突、删除恢复、远端晚到资料和备份恢复。界面专项覆盖空工作区、知识库管理、列表标题、对话范围和面板显隐；真实网盘传输仍按原计划待验收。
