# 0005: Git 版本与加密目录交接

日期：2026-10-10。状态：已被 [0006 当前内容同步](0006-current-content-sync.md) 替代。以下保留原决定的历史背景，当前产品不再提供 Git 提交或本地独立备份。

## 决定

每知识库用本机裸 Git 管理不可变知识快照；SQLite 保留编辑历史、索引和本机设置。共享偏好及设备策略使用独立范围。用户明确保存版本、发布、确认客户端上传、检查本地下载、拉取合并。不申请百度 API，不把 SQLite 或 Git 仓库放进网盘。

首次发布完整 Git bundle，后续 bundle 带基础依赖。每次发布拥有独立 ID，清单最后写入。包与原文件均使用 AES-256-GCM 加密；原件按 SHA-256 寻址并拆成 4 MiB 二进制块，避免 JSON/Base64 膨胀。传输适配层只声明本地发现/读写能力，没有云端查询、上传确认或客户端空间释放能力。

SQLite 中的持久化操作日志连接 Git 提交与数据库导入；中断后完成原操作，不能假设两种存储原子提交。导入登记、附件绑定与知识版本一同落库；同一记录并发修改仍保留双方，Git 合并提交保留两个父提交。

设备名称与主力角色追加为共享版本；角色并发保留冲突。次要设备释放系统托管原件需要明确确认、当前主力角色的文件内容回执、干净版本及无使用/保留引用。同步空间的密文只能由用户通过客户端“仅释放本地”处理，应用不删除它们。

### 2026-10-10 需求调整

原方案要求先记录隔离客户端能力验证。用户明确取消该前置条件，改为直接采用百度同步空间，开发重点放在本系统同步机制。移除问卷、对应界面 API 与释放门槛，已有记录留存但不授予权限；不把取消门槛记作客户端实测通过。可选双机部署联调只记录实际应用集成现象，不再重新认证百度产品能力。

## 被拒绝的替代方案

- 直接同步 Git 工作目录/裸仓库：客户端没有 Git 引用和对象的事务保证。
- 百度 API：本轮明确不要求用户申请。
- 将视频写入 Git 对象库：不符合文件独立传输和设备空间策略。
- 依赖百度历史版本保存旧原件：保留策略不在应用控制内。
- 用文件出现或用户确认冒充云端核验：没有可靠证据。

## 兼容与限制

旧实体 ID、版本、冲突和原件不重写；用户第一次保存版本将现有历史纳入 Git。旧目录协议代码保留供兼容测试，不再由 Service 定时运行。v2 使用独立目录命名空间，两台必须更新源码；需要接收的旧包须先在旧版本完成，v2 不自动转换旧包。

独立备份 format 1 增加可选 Git bundle 描述。恢复保留归档 Git 引用，与本机历史合并，不替换当前提交指针；下次保存版本连接归档历史。旧备份仍可读取。备份目前为本地明文，禁止放进已配置同步目录，云端加密备份另待实现。

主力机历史孤立原件释放暂未开放；当前策略更保守，主力机所有原件保留。单次 Git 快照/包上限 128 MiB、十万条历史，超大知识库和 GB 视频性能尚未验收。发布支持失败后复用已完成分块，但没有自动按磁盘预算暂停的批次调度；空间不足会报错并保留重试状态。这些属于 StudySelf 后续开发与性能验证范围。
