# 主力机设备管理

## 范围

用户确认：主力机可修改设备名称、停用/恢复设备、转移主力机。管理状态随现有加密目录通道共享，主力角色不改变知识冲突合并规则。不删除设备历史、笔记、原件或网盘文件，不自动操作真实设备角色或发布真实数据。

转移采用两步确认：当前唯一主力机发起，目标设备接收最新管理状态、确认并校验本机原件后接管。旧主力机在接管前继续保留原件；允许取消尚未完成的请求。没有主力机时允许本机初次设定，角色冲突由冲突参与设备明确处理。

停用是更新客户端执行的同步参与限制，不是共享密钥撤销、远程擦除或强制控制离线电脑；其他电脑接收后生效。被停用设备仅接收管理状态以获取恢复通知，不继续发布或导入知识内容；其他设备忽略其当前发布，已接收的知识及历史保留。

## 实现与兼容

- 管理操作采用带操作者、角色依据和父记录的不可变记录，校验基础快照及请求标识，冲突不按时钟覆盖；设备状态冲突暂停其同步，名称冲突保留候选供主力机重新命名。
- 转移请求绑定当前角色及管理记录，接管重验目标、完整性及版本。角色变化后旧请求不再生效。
- 含设备管理信息使用 format 5 清单，保留 v3/v4 读取及原删除凭据。旧客户端拒绝新格式，参与设备需一起升级。受信任界面具名方法执行管理，不向外部 Agent 开放。
- 设备列表增加短标识、状态和操作，区分同名设备，非主力机只展示可用的本机确认入口。
