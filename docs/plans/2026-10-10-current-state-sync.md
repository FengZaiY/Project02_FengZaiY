# 当前内容同步与笔记修改历史

用户取消运行时 Git 版本管理和本地独立备份。源码仓库 Git 不受影响，旧用户仓库、备份和传输文件不删除。

## 设计

- SQLite 修改记录继续保留稳定身份、父记录、冲突、回收站及逐条恢复；无需手动提交。
- v3 使用每设备独立的加密最新清单，指向不可变内容对象。清单包含完整修改记录与文件索引，不依赖以前的清单或 Git 基础包。多设备并发清单一起合并，不按时间覆盖。
- 全工作区统一发布；设备策略与偏好同行，私密设置、数据库和本机路径不同行。百度管理清单文件的云端历史；恢复旧清单仍需其引用对象与密钥，不宣称百度提供跨文件事务快照。
- 发布前冻结内容并估算增量占用，以当前可用空间及保留空间规划批次。对象落盘后持久化进度；支持暂停、继续及批次上传确认。客户端负责上传和仅释放本地，不删除中转对象腾空间。
- 接收使用持久化分块进度与临时原件；重启后校验已保存分块，从有效断点继续。完整校验后才绑定，失败不入库或伪报完整。
- 新电脑一次拉取本地已下载的各设备最新清单，无需提交共享版本或回放历史发布。显式拉取保护未保存标签，已保存并发修改通过修改记录合并。
- v2 未完成日志只恢复其知识记录和本地绑定，不再执行 Git；旧协议文件不混写。旧设备须更新并发布 v3，才能向新电脑提供无 Git 的最新内容。
