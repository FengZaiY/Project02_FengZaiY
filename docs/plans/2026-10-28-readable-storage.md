# 可读资料目录与 MCP 统一整理方案

日期：2026-10-28。状态：源码实现和实际存储迁移已完成，现有资料分类命名方案已通过 MCP 提交，等待本机内容确认。取代本文件此前“原件随笔记/共享资料目录放置”的建议。

## 1. 目标与边界

用户在软件和资源管理器中都能按相同分类找到资料。用户原件按“资料 → 分类 → 资料主题 → 中文文件名”存放；知识笔记按“知识库 → 笔记层级”组织；数据库、完整富内容结构、历史、内部索引和本机配置等由系统管理，目标归入工作区内部的 `.fengzai-y`。哈希用于校验与识别，不作为用户查找原件的主要路径。

AI 提出笔记、资料和逻辑位置的一体化方案，Agent 通过 MCP 收集并提交，由用户在 FengZaiY 内预览、部分确认，系统负责创建目录、写入文件和维护引用。Agent 不直接写工作区目录或数据库。系统设置、永久删除、秘密、安装授权等边界不变。

继续采用独立本机数据库和现有百度加密传输机制；数据库/WAL、设备私密配置不参与同步。本轮交付源码与预览，不打包、提交或推送。先使用隔离数据验证，再通过系统迁移流程整理用户授权的现有资料；外部来源与未知文件保留。

## 2. 目标目录

下例是用户给定场景，不能据此为新用户预置“装修”分类或示例内容。知识库继续以其名称直接位于工作区根目录，符合已有知识库根文件夹约定。

```text
工作区/
  资料/
    装修/
      瑶林整装合同模板/
        01_封面.jpg
        02_合同条款.jpg
        合同模板.docx
  装修知识库/
    合同审核/
      正文.md
      资料引用.md
      付款条款/
        正文.md
    收集与草稿/
      合同讨论要点/
        正文.md
  导出/
  .fengzai-y/
    database/
    metadata/
    history/
    staging/
    cache/
```

内部子目录名是建议，按现有职责确定，不为了目录齐全创建空目录。秘密与本机加密配置保留既有保护方式；不能把秘密写入可读笔记、资料清单或普通 JSON。数据库备份机制不因目录迁移重新引入。启动位置锚点、运行时必须在工作区外的 Electron 配置/更新缓存保留其必要位置，不为统一外观擅自移动。

- 资料分类表示大类，资料主题表示一份合同、一门课程、一个项目材料包等具体资料组；每个资料条目有一个主要主题。首版采用分类/主题两层，不增加无限层文件夹管理。
- 分类和主题由用户创建或 AI 提议后确认，软件资料页展示同一结构；集合、标签、笔记引用可以多选，但不额外决定物理目录。
- 文件使用用户可读中文名称与真实扩展名，保留原始文件名元数据。AI 可建议中文名及顺序号，不更改内容、编码或扩展名含义。
- 中文是优先的可读命名方式，不强行翻译已有清晰名称、型号或代码。没有确认的改名建议时保留原文件名；显示名称、实际文件名不同须同时展示，不用界面改名掩盖磁盘仍为哈希名。
- 有序图片可用 01、02 等编号；排序与物理改名分开，普通拖动排序不自动批量改名。
- 未确定归属的已完整导入原件可暂放“资料/待整理/本次收集主题”，按实际需要创建并标明待整理；分块临时内容只在内部 staging，不呈现为已完整资料。
- 固定目录、知识库名称冲突、Windows 禁止字符、同名不同文件、大小写与长路径统一处理。预览展示最终实际名称；仅冲突时添加短标识，不覆盖外部已有目录或文件。

## 3. 单一原件、多处引用

一个资料身份对应一份当前受管原件，可被多篇笔记、多个集合及业务记录引用。原件位置由主要分类/主题决定；增加引用、移动笔记或删除其中一个引用都不会迁移或删除原件。

笔记目录提供可读的“资料引用.md”，显示资料名称、分类/主题和相对文件链接；原件不复制进各笔记目录。跨知识库仍使用稳定 ID，路径只作各电脑本机映射。不存在或尚未下载的原件明确显示待下载，不生成空文件冒充成功。

内容相同不等于业务身份相同：现有重复条目不因重构自动合并。迁移需预览重复/共享情况，允许用户选择保留归属、引用已有资料或保留独立资料。对用户明确保留的独立身份，不擅自折叠；“一个原件、多处引用”针对复用同一资料身份的正常流程。

分类/主题或文件改名、移动，由系统执行受管任务，并刷新本机相对链接。笔记调整只更新笔记目录；资料分类调整只移动相应原件，跨板块引用保持有效。外部程序改写或占用时保护现场并报告待处理，不覆盖未知变化。

分类/主题本身使用稳定身份，改名不重建资料；删除含资料或待执行方案的分类/主题前须先处理归属和依赖，不级联清空原件。回收一个笔记或删除一条引用，不等于回收资料。资料内容被外部改动时，不将新字节直接绑定到旧哈希或静默覆盖历史。

## 4. AI → MCP → 确认 → 系统落盘

1. Agent 通过 MCP 读取可用知识库、笔记层级、资料分类/主题及已有引用；管理查询可含本机实际路径，但不能借此直接读写目录或数据库。
2. 用户提供的文件通过 MCP 导入；对话提炼内容形成草稿和来源说明。不恢复内置聊天，也不默认保存整个外部会话。
3. AI 提交统一方案：笔记新增/融合及上下级、原资料归属、建议中文文件名/顺序、资料复用、旧位置到新位置的逻辑变化，并说明理由和未覆盖内容。
4. FengZaiY 预览正文变化、目标分类/主题、实际本机路径、原件引用、迁移数量与空间、冲突和依赖；用户可整批确认、分项确认或要求重做。缺少必要分类/主题/上级项时提示，不暗中扩大确认。
5. 确认时重新校验版本与未保存编辑，事务记录业务修改和持久化文件任务；随后系统创建目录、复制/校验文件、更新绑定与正文引用。MCP 只能查询执行状态，不能自我确认。
6. 分开显示“业务已入库、原件已校验、目录已完成”；失败保留任务与旧可用位置，可继续/重试，不把数据库写入成功当成全部落盘完成。

现已扩展分类/主题查询、propose/materialItems、依赖解析、资料组织预览与结果查询，并增加五项分块上传工具。SDK 专项验证新 schema、待确认项修改、重复请求、依赖审批及过期保护；实际本机 MCP 已提交 14 份资料的组织方案。

内容方案与路径任务共用可追溯的操作批次，但不假设 SQLite 与文件系统能同时提交。确认后、文件任务完成前，读取继续使用已验证的旧绑定；新路径校验并切换成功后刷新本机引用清单。执行重试须重新校验资料版本、分类/主题和目标名称，不能将已过期的计划强行落盘。多处引用的批量变化须在同一预览中呈现，避免用户仅看到一篇笔记而误批准影响全部引用者的资料改名。

assetWrite 单文件上限保留 16 MiB。新增大文件协议使用最多 4 MiB 分块、凭证独立会话、分块/完整 SHA256、空间预检及持久化断点；重启后可查询 received 继续，完整校验前不绑定原件。取消仅清理本会话暂存对象；授权撤销立即拒绝继续访问。过期或被撤销会话的自动暂存清理尚未完善，不能宣称零残留。不提供任意本机路径读取。

## 5. 软件与资源管理器体验

资料页按“分类 → 主题 → 文件”浏览，共用搜索、类型、标签、引用情况及待整理筛选。集合继续表示多维分组，不能伪装为原件存放目录。知识页仍按知识库及笔记层级浏览。

详情同时显示逻辑位置、实际本机路径、原文件名、引用者和本机就绪状态，提供打开所在目录、定位文件、复制路径。没有原件时提供现有下载/导入入口，不显示假路径。资料结构属于业务分类，不开放任意系统目录管理。

笔记生成可在外部阅读器打开的正文与资料链接；富内容保真结构与历史放系统内部。复杂图表提供可读表示并保留源结构，不能将 HTML 直接写成 .md 后声称完整可读。用户主动导出进入可读“导出”目录。

资源管理器浏览/打开属于本期目标；外部移动、改名、正文编辑自动回写数据库不作为本期承诺。检测到外部修改时引导重新关联或导入，不覆盖、不根据缺失文件传播删除。

## 6. 旧资料及内部数据迁移

### 原件与正文

统一扫描本机已登记的绑定，预览旧新路径、名称、归属、重复/共享引用、未下载项、冲突和空间预算。归属无法确定时由 AI 提议或用户选择，不能把第一个引用任意当归属。

用户确认后创建可重试迁移任务，分批复制到临时目标、校验大小/哈希并持久化，然后按原版本更新绑定。旧原件在确认新绑定和读取可用前始终保留；原文件内容、资料身份、笔记引用及修改历史不重建或改写。异常项保留旧位置，不能全批误报成功。

迁移完成后，旧托管副本可单独预览确认清理，逐文件核验无有效绑定/读取且内容一致；用户导入源、未知文件、外部修改、历史必需文件保留。正常使用无需长期保留两套当前原件，迁移期间允许临时占用。不递归清空 .fengzai-y，不误删其中历史/导出/密钥。

历史版本的旧原件若仍有历史或冲突引用，可在内部受管区域保留，明确属于不同内容版本而非当前原件的展示副本；释放继续遵守现有保护规则，本次不扩大释放权限。

### 系统内部数据

将数据库、索引和内部文件归入 .fengzai-y 是独立迁移阶段。须停写、关闭 SQLite 和释放句柄，通过持久化迁移记录、校验和可恢复的启动切换完成；不能移动正在运行的 SQLite/WAL。保留旧布局读取与密钥解密能力，失败恢复到已验证的原位置，重启后重新核验笔记数量、历史、资料绑定和秘密可解锁性。

旧 .fengzai-y 的归属标记与资料仍须识别，不能直接重新创建为另一设备所有。工作区外启动锚点继续指向正确根目录；本机私密位置不随同步分享。已有 exports 的迁移同样单独预览，保留用户文件和未知内容。

## 7. 同步和兼容

新增资料分类、主题及主归属是共享业务结构，使用稳定 ID 和基础版本，按现有并发机制合并。路径名称是本机实现结果，不能把一台电脑的绝对路径同步给另一台。多端独立重建目录并校验原件；离线改名/移动冲突保留双方方案，不能按最后到达覆盖。

新增结构使用 format 9，旧格式继续读取，旧冻结计划须重建。隔离双目录测试验证新电脑恢复分类和原件及重复导入。百度目录继续只存加密传输内容，不直接同步 .fengzai-y 数据库或未完成迁移目录；同步电脑须共同升级。
