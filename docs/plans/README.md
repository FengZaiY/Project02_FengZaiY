# 实施计划

跨模块、协议、数据迁移和多阶段任务在此保存计划。普通小修复不强制建立文件。

文件名使用 `YYYY-MM-DD-short-topic.md`。同一任务持续更新同一份计划；完成后保留原文件，不生成重复的“最终版”。

## 模板

```markdown
# 任务名称

状态：待开始 / 进行中 / 阻塞 / 已完成
创建日期：YYYY-MM-DD
最近更新：YYYY-MM-DD

## 目标与验收
- 可验证的目标：
- 不在本次范围：

## 现状和影响
- 涉及模块：
- 数据兼容与安全边界：

## 实施步骤
- [ ] 步骤一
- [ ] 步骤二

## 验证
- 命令或人工操作：
- 实际结果及证据：
- 尚未验证：

## 风险与回退
- 风险：
- 不破坏用户数据的回退方式：

## 交接
- 已完成：
- 下一步：
- 需要用户或外部条件：
```

逐步更新完成项，记录真实阻塞原因；不要写入密钥、真实账号或私人文件内容。重要架构取舍应另写 [决策记录](../decisions/README.md)，不长期藏在任务计划中。
