# 日常交互与后台性能优化

目标：减少查询和页面切换延迟、编辑器不必要重建、目录全量投影及原件重复解码。保留保存、冲突、权限、引用、哈希校验与失败重试，不改变共享历史格式。

## 阶段

1. 查询：当前头元数据索引与数据库分页；保留冲突、回收、跨分支搜索和确认状态筛选语义。缓存按实际数据库变化失效，事务回滚不留下过期结果。
2. 界面：按业务页面加载列表和树，轻量轮询；同一笔记未变化时保留编辑器和撤销，切换及保存期间输入继续保护。
3. 目录：保存可重试的逐记录投影指纹，后台只处理变化项；父级/引用/绑定变化须传播，显式维护保留完整校验，失败及中断重跑。
4. 大资料：有界缩略图缓存与按需加载、离开取消；文件身份变化失效。耗时文件校验使用有界工作线程，继续同句柄读和读后重验，失败不能降级绕过校验。
5. 验证：隔离数据的优化前后基准、事务/冲突/同步/目录/原件失败路径、浏览器及源码桌面；核对原预览身份再重启。更新架构、约定、状态和验证记录。

基线（2026-10-29，同机源码 Node 24.16.0）：1000 笔记 state 205/123/125ms，noteTree 115/117/118ms，records 前150条 45/37/38ms；10000笔记 Store.summary 234ms、列表293ms、搜索316ms。仅隔离样本，不代表正式安装版卡顿已被完整复现。

只交付源码/预览；不提交、不推送、不打包，不操作正式业务资料。

## 实施结果

阶段 1 至 4 已完成：连接内索引与缓存、按页加载与原编辑器刷新、增量投影、有界缩略图与文件线程。阶段 5 核心及浏览器/源码桌面验证已通过；最终预览身份与维护检查见 [验证记录](../verification-performance-2026-10-29.md)。
